# 医疗咨询模型与查询器简化设计

## 目标

医疗功能只提供最基础的信息咨询，不诊断、不替代医生。查询器负责提供与数据库严格对齐的证据；模型负责理解口语、选择是否追问和组织自然语言。

本设计暂不修改当前 `agents/Medical/retriever.py`，用于后续简化重构。

## 查询器职责

输入保持为用户完整原话，输出只分三类：

1. `matched`：数据库中存在直接、明确、可追溯的匹配，返回少量 evidence。
2. `need_more_info`：可能匹配但信息不足，返回一至三个 questions，不给出具体结论。
3. `not_supported`：数据库没有严格匹配，或问题超出简单咨询范围，建议咨询专业医生。

查询器不负责复杂临床分诊，不构建大规模危险触发规则，不把向量相似结果当成事实。dense/hybrid 只用于召回候选；最终结论必须通过实体、关系或文档证据的严格对齐校验。

建议返回协议：

```json
{
  "status": "matched|need_more_info|not_supported",
  "query": "用户原话",
  "evidence": [],
  "questions": [],
  "message": "工具边界说明"
}
```

## 模型自由度与限制

- 可以改写措辞、总结证据、给出低风险的一般性提醒。
- 可以在 `need_more_info` 时从 `questions` 选择最重要的一条调用 `query`。
- 如果模型判断问题危险、复杂或无法可靠解决，可以直接建议寻求专业医生帮助。
- 不得新增 evidence 中不存在的疾病、药物、检查、科室或治疗结论。
- 第三轮仍无充分证据时必须用 `speak` 说明无法可靠判断并建议专业就医。

## 后续重构验收

- 完全匹配的数据库问题能返回来源明确的有限答案。
- 模糊或缺失信息不会输出具体医学结论。
- dense 相似但无法结构化验证的候选只能触发追问或 `not_supported`。
- 多轮最多三轮，最终始终通过 `speak` 收束。
